Sampled-Mode Workflow: scRNA-seq without Spatial Coordinates

2026-04-20

Overview

Ligand–receptor-mediated (LRM) signaling inference requires defining which cell pairs to score. When spatial coordinates are available, physical proximity provides a principled basis for that definition. Without coordinates — as in most droplet-based scRNA-seq experiments — the choice is less obvious.

The naive approach of scoring every possible cell pair is computationally intractable: 14,000 cells produce nearly 200 million ordered pairs, each requiring scores for hundreds of LRM pairs. More importantly, most of those pairs are biologically uninterpretable because the cells never coexisted in the same microenvironment.

NICHESv2’s sampled mode solves this by drawing a stratified random sample of cell pairs within each cell-type stratum. The sampling is reproducible (fixed seed), keeps the cell-type composition of the data intact, and produces an edge list compact enough for downstream analysis. The result is a NICHESObject with the same slot structure as spatial mode, enabling identical downstream workflows.

This vignette demonstrates the sampled-mode workflow using the ifnb dataset: ~14,000 PBMCs profiled under control (CTRL) and interferon-beta stimulation (STIM) conditions, annotated with 14 cell types.

Step 1 — Ingest from Seurat

extract_NICHESInputs_Seurat() extracts the raw count matrix and cell metadata from a Seurat object. It detects V4 and V5 assay structures automatically, so no manual conversion is needed.

Step 2 — Why sample splitting matters

The ifnb dataset contains cells from two independent conditions profiled in separate batches. Constructing edges across conditions would pair a CTRL cell with a STIM cell — a combination that never occurred in any biological sample. Such cross-condition edges inflate apparent connectivity and make the results uninterpretable.

Setting sample.col = "stim" instructs NICHESv2 to build edges within each condition independently, then merge the resulting objects. Every edge in the final NICHESObject is guaranteed to connect two cells from the same condition.

# Without sample.col: edges are built across all 13,999 cells simultaneously.
# CTRL cells can be paired with STIM cells — biologically meaningless.
#
# With sample.col = "stim": NICHESv2 processes CTRL (6,548 cells) and
# STIM (7,451 cells) separately, then merges. All edges are within-condition.
#
# Rule of thumb: if your experiment has multiple samples, donors, replicates,
# capture areas, or conditions, always set sample.col.

Step 3 — Build the NICHESObject

niches.ifnb <- create_NICHESObject(
  count.mtx     = inputs$count.mtx,
  meta.data     = inputs$meta.data,
  LRM.db        = load_LRM_database("fantom5", species = "human"),
  mode          = "sampled",
  species       = "human",
  sample.col    = "stim",
  cell.type.col = "seurat_annotations",
  method        = "product",
  n.cores       = 4L,
  verbose       = TRUE
)

load_LRM_database("fantom5", species = "human") loads the bundled FANTOM5 ligand–receptor database for human — no internet connection or additional packages required.

Step 5 — Pseudobulk connectivity

Single-cell edge scores can be aggregated to the cell-type level with compute_PseudoBulk_Connectivity(). This function collapses expression to pseudobulk profiles per cell type, scores all LRM pairs across all type–type combinations, and returns a flat data.table:

pb <- compute_PseudoBulk_Connectivity(
  count.mtx     = inputs$count.mtx,
  meta.data     = inputs$meta.data,
  LRM.db        = load_LRM_database("fantom5", species = "human"),
  cell.type.col = "seurat_annotations",
  method        = "product",
  n.cores       = 4L,
  verbose       = TRUE
)

dim(pb)
#> [1] 63858     7

head(pb[, .(SendingType, ReceivingType, LRM, score, score.norm)], 5)

Note that compute_PseudoBulk_Connectivity() operates directly on the count matrix and metadata — it does not require a NICHESObject as input. This makes it straightforward to run as a standalone summary step before or after sampled-mode inference.

Visualising cell-type connectivity

To get a broad view of which cell types are most actively communicating, aggregate score.norm across all LRM pairs and display the result as a heatmap. The values are log1p-transformed before plotting because total connectivity spans several orders of magnitude across cell-type pairs.

# Sum raw scores across LRM pairs per type pair — score.norm is within-pair
# proportional and sums to ~1 per pair, making it unsuitable for cross-pair comparison.
pb.agg <- pb[, .(total.score = sum(score)),
             by = .(SendingType, ReceivingType)]

ggplot(pb.agg, aes(x = ReceivingType, y = SendingType,
                   fill = log1p(total.score))) +
  geom_tile(colour = "white", linewidth = 0.4) +
  scale_fill_viridis_c(option = "plasma", name = "log1p(score)") +
  labs(
    title    = "Pseudobulk LRM Connectivity",
    subtitle = "ifnb dataset — FANTOM5 database",
    x        = "Receiving cell type",
    y        = "Sending cell type"
  ) +
  theme_minimal(base_size = 11) +
  theme(
    axis.text.x      = element_text(angle = 45, hjust = 1),
    panel.grid       = element_blank(),
    legend.key.width = unit(0.4, "cm")
  )

The heatmap rows are sending cell types and columns are receiving cell types. Brighter tiles indicate higher aggregated normalised connectivity for that directional pair across the full FANTOM5 LRM catalogue.

What’s next

This vignette covered the sampled-mode workflow for annotated scRNA-seq data without spatial coordinates. Because sampled mode does not assign physical positions to cells, in-situ plotting is not available — CellToCell_InSitu() requires spatial coordinates in $cell.meta.

For spatially resolved data (Visium, MERFISH, Xenium, etc.), see the next vignette: Spatial-Mode Workflow, which covers radius parameter selection with Explore_Radius_Neighborhood() and in-situ LRM connectivity maps with CellToCell_InSitu_Single_LRM().
